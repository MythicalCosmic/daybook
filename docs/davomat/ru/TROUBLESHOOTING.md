# Неполадки и их устранение

Начните отсюда — на сервере, из папки с кодом (`/opt/davomat`):

```bash
bash deploy/davomat/status.sh
```

Скрипт ничего не меняет и показывает сервисы, сайт и его сертификат, адрес для терминалов, worker и
бота, резервные копии, диск и последние ошибки, а в конце — что требует внимания. В командах ниже
`dc` означает `docker compose -f docker-compose.davomat.yml`:

```bash
alias dc='docker compose -f docker-compose.davomat.yml'
dc ps                        # сервисы и их состояние
dc logs --tail 100 backend   # лог одного сервиса (caddy, backend, worker, beat, bot, db, backup)
dc logs -f backend           # следить за логом
```

## Сайт не открывается

- **Сразу после установки, несколько минут**: при первом запуске создаётся база данных.
  `dc logs backend` показывает строки `Applying …`; дождитесь `Listening at`.
- **Ошибки сертификата / «connection refused» снаружи**: Caddy получает сертификат от Let’s
  Encrypt, а Let’s Encrypt должен достучаться до сервера **из интернета по портам 80 и 443**.
  Проверьте файрвол (`ufw status`), облачный файрвол провайдера и то, что DNS-запись `A` домена
  указывает на сервер (`getent hosts <domain>`). `dc logs caddy` покажет, что не получилось. После
  исправления Caddy сам попробует снова (или `dc restart caddy`).
- **Слишком много неудачных попыток получить сертификат**: после пяти неудач Let’s Encrypt
  приостанавливает выдачу для этого имени на час. Устраните причину, подождите, затем
  `dc restart caddy`. `<server IP>.nip.io` всегда указывает на сервер и хорошо подходит для
  проверки.
- **«Bad Request (400)»**: адрес в браузере не совпадает с адресом в `.env`. Davomat отвечает только
  на `DOMAIN` (`DJANGO_ALLOWED_HOSTS`). После их изменения: `bash deploy/davomat/update.sh --here`.
- **Сервис постоянно перезапускается** (`dc ps` показывает `Restarting`): причина в его логе
  (`dc logs --tail 100 <service>`); чаще всего это неверное или отсутствующее значение в `.env`.

## Терминал не может достучаться до сервера

В карточке терминала так и остаётся «Ждём первое событие терминала».

1. **С компьютера в сети терминала** откройте (или проверьте через `curl`) адрес терминала со
   страницы настройки по HTTP: `http://<server>/api/v1/devices/hik/<code>/`. Ответ должен быть
   `{"statusCode": 200, "statusString": "OK", …}`.
   - Ответ есть: сеть в порядке, дело в настройках терминала (шаг 2).
   - 404: неверный код (снова скопируйте URL со страницы настройки; после выдачи нового кода старый
     перестаёт работать).
   - Ответа нет: из этой сети сервер недоступен по порту 80 (файрвол офиса или сервера) или неверен
     адрес сервера.
2. **На терминале** (HTTP Listening): хост точно как на странице настройки, URL с `/` в начале и в
   конце, порт `80`, протокол `HTTP`, всё сохранено. Чтобы достучаться до чего-либо за пределами
   своей сети, терминалу нужен **шлюз** (gateway) в его сетевых настройках (Configuration › Network
   › Basic Settings), а если хост задан именем — ещё и DNS-сервер: с IP-адресом DNS не нужен.
3. `dc logs --tail 50 backend | grep devices` покажет каждый запрос, пришедший от терминала.

## HTTPS на старой прошивке

Многие терминалы не умеют работать по HTTPS с современными сертификатами (DS-K1T341AMF с прошивкой
V3.2.x не подключается никогда, как его ни настраивай). Используйте **HTTP на порту 80**: Davomat
никогда не перенаправляет адрес терминалов на HTTPS и принимает события как есть. Защищает его
секретный код в URL; если адрес утёк, выдайте терминалу новый код (на его странице, одним нажатием)
и введите в терминал новый URL.

## Накопленная история

«Терминал сначала отправляет старую историю» в течение нескольких часов после подключения — это
нормально: он выгружает каждое когда-либо сохранённое сканирование, начиная с самого старого, в
своём темпе (примерно одно-два в секунду; 40 000 старых сканирований занимают рабочий день).
Davomat их пропускает (никаких приходов и сообщений) и подсчитывает в карточке терминала. Живые
сканирования пойдут сразу после этого. Не перезагружайте и не сбрасывайте терминал: он начнёт
заново, а сброс к заводским настройкам удалит внесённые лица.

## Часы

- **«Часы терминала отстают на N мин» или «Часы терминала спешат на N мин»**: задайте часовой пояс
  терминала (GMT+05:00 для Ташкента) и NTP (`pool.ntp.org`) в Configuration › System › Time
  Settings. Обычная причина — заводской часовой пояс (часто GMT+08:00) или часы, выставленные
  вручную.
- **«Часы терминала сильно отстают: живые сканирования выглядят старыми и пропускаются»**: на
  терминале неверная дата (расхождение в дни и больше): настройте её, как описано выше.
  Сканирования сразу снова начнут сохраняться.
- **Часы сервера**: `timedatectl` должен показывать `System clock synchronized: yes`; если нет:
  `timedatectl set-ntp true`.

## Сканирования, которые не учитываются

- **«Не привязан»**: номер никому не принадлежит. Если новые сотрудники создаются из неизвестных
  номеров (так по умолчанию), это бывает только с отложенными номерами; иначе привяжите номер на
  странице Face ID › Люди.
- **«Повтор»**: второе сканирование в течение нескольких минут после предыдущего; ничего не
  меняется. Это нормально.
- **Уволившийся сотрудник**: его сканирования записываются, но не учитываются.

## Telegram

- **В разделе Настройки › Telegram токен отмечен как недействительный**: его отозвали или ввели с
  ошибкой: BotFather › `/mybots` › ваш бот › API Token, затем вставьте токен заново.
- **Бот не отвечает**: `dc logs --tail 50 bot`. «No Telegram bot token yet» — вставьте токен.
  «Conflict: terminated by other getUpdates request» — тот же токен использует другая программа
  (старый сервер, тест): остановите её или отзовите токен в BotFather и вставьте новый. Сервер
  должен иметь исходящий доступ к `api.telegram.org` по HTTPS.
- **Кому-то не приходят сообщения**: человек должен открыть свою ссылку, нажать Start и не
  блокировать бота; на его странице Telegram должен быть отмечен как привязанный.

## Забытый пароль

Новый пароль задаёт администратор в разделе Настройки › Пользователи и роли. Если войти не может
никто, на сервере:

```bash
cd /opt/davomat
docker compose -f docker-compose.davomat.yml exec backend python manage.py changepassword <username>
```

Логины, которые могут входить в систему:

```bash
docker compose -f docker-compose.davomat.yml exec backend python manage.py shell -c \
  "from django.contrib.auth import get_user_model as U; print([u.username for u in U().objects.filter(is_active=True) if u.has_usable_password()])"
```

Пять неверных паролей блокируют этот логин с этого компьютера на 15 минут: просто подождите.

## Диск и память

- `df -h` и `docker system df`: старые образы удаляются командой `docker image prune -f`.
- `du -sh backups`: резервные копии хранятся 14 дней (`BACKUP_KEEP_DAYS` в `.env`); скопируйте их
  в другое место и удалите ненужные.
- Снимки сканирований удаляются через заданное в Face ID › Настройки число дней.
- Если памяти меньше 4 ГБ, сборка может завершиться ошибкой: добавьте swap
  (`fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`) или
  используйте готовый образ (INSTALL.md, раздел 8).

## Обновление прошло неудачно

Если новая версия не запускается, `update.sh` выводит, как вернуться назад. Вкратце:

```bash
git -C /opt/davomat checkout <the previous commit>     # или распакуйте предыдущий релиз
bash deploy/davomat/update.sh --here --no-backup
bash deploy/davomat/restore.sh backups/<date>_<time>-pre-update   # только если нужно вернуть и данные
```

## Начать с нуля

Чтобы стереть всё (все данные, безвозвратно), сохранив `.env`:

```bash
docker compose -f docker-compose.davomat.yml down -v
bash deploy/davomat/install.sh
```

## Как попросить помощи

Пришлите вывод `bash deploy/davomat/status.sh` и последние строки лога проблемного сервиса
(`dc logs --tail 200 <service>`). Никогда не присылайте `.env`: в нём ключи.
